# USB-протокол и прошивка

## Канал Windows ↔ M82

Используется существующий HID-интерфейс `MI_03`. Его Consumer Control Input Report сохраняется. В ту же коллекцию добавлен Feature Report на 16 байт без ненулевого Report ID. Windows API передаёт 17 байт: нулевой ID и 16 байт payload.

| Смещение payload | SET | GET |
|---|---|---|
| 0–3 | ASCII `M82T` | ASCII `M82T` |
| 4 | Opcode `1` | Opcode `2` |
| 5 | Версия `1` | Статус |
| 6–7 | Год uint16 little endian | Год |
| 8 | Месяц | Месяц |
| 9 | День | День |
| 10 | Час | Час |
| 11 | Минута | Минута |
| 12 | Секунда | Секунда |
| 13–15 | Резерв, нули | Резерв |

GET-статусы: `0` — готово; `1` — RTC не открыт; `2` — применение ожидает; `3` — пакет отклонён или очередь недоступна. Корректный SET может повторяться после статуса 3. Пока буфер занят, следующий SET не перезаписывает его.

SET проверяет magic, opcode/version, годы 2000–2099, месяцы, длину месяца с учётом високосного года, часы, минуты и секунды. Время передаётся как локальное время Windows без часового пояса: именно его показывает дисплей. В проекте нет команды телефонного вызова и Bluetooth-эмуляции.

## Контекст выполнения

EP0-обработчик копирует проверенные данные в постоянный буфер и вызывает `os_taskq_post_type("app_core", Q_CALLBACK, ...)`. Очередь получает callback и указатель на постоянную структуру `sys_time`. Штатное обновление RTC/будильников выполняется в `app_core`, затем флаг занятости снимается. Это не вызов записи часов/VM непосредственно из USB-прерывания.

Буфер занимает 24 байта в исходном зазоре выравнивания между BSS (`0x16808`) и RAM-кодом (`0x16820`). Обнуление BSS увеличено до `0x16820`; существующие переменные и RAM-код не перемещены. Эти адреса относятся только к поддерживаемой ревизии.

## Адреса проверенной ревизии

| Функция | Виртуальный адрес |
|---|---|
| HID setup entry | `0x01E32D2A` |
| Продолжение оригинального обработчика | `0x01E32D2E` |
| `usb_set_setup_recv` | `0x01E32D16` |
| Обёртка копирования EP0 | `0x01E32DE4` |
| `usb_set_data_payload` | `0x01E32952` |
| Инициализация HID endpoint | `0x01E32CEE` |
| `dev_ioctl` | `0x01E0CF6E` |
| Штатное обновление RTC | `0x01E3F732` |
| `os_taskq_post_type` в RAM-коде | `0x0001716A` |
| Новый обработчик | `0x01E5A9C6` |

`IOCTL_GET_SYS_TIME = 19`, `IOCTL_SET_SYS_TIME = 20`. Общий дескриптор конфигурации и отдельный HID-ответ объявляют одинаковые 67 байт report descriptor. Вход в прежний обработчик заменён переходом; для остальных запросов выполняются заменённые инструкции пролога и продолжается исходный код.

## Упаковка

Основной код расширен на 576 байт; добавленные обработчики и дескриптор занимают 559 байт. Ресурсы сдвинуты без изменения содержимого. Конец ресурсов — `0x66986`, до наблюдаемой области настроек `0x67000`.

Обновляются CRC16 `app.bin`, окружающего application area и заголовков. Сохраняется SFC-шифрование с ключом конкретной поддерживаемой версии. Пакет содержит 13 целых 4-КиБ секторов и их хеши; не содержит полную flash и mutable-область.

Распаковщик upstream неполно трактует reserved-area адреса: его вывод VM `0x69000` не использовался как разрешение писать туда. Наблюдаемые записи настроек начинаются с `0x67000`, поэтому именно эта более строгая граница зафиксирована в инструментах.
