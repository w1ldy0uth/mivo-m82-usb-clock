# Подтверждённые результаты и ограничения

## Аппаратная проверка — 9 ноября 2026

На одной MIVO M82 с поддерживаемой ревизией:

- Два исходных чтения flash совпали побайтно.
- После записи сверялся каждый изменённый сектор и вся flash.
- Windows приняла HID Feature Report 17 байт и исходный Input Report с 16 кнопками.
- До синхронизации RTC показывал `2024-05-05 18:30:33`.
- После USB SET и повторного GET: `2026-11-09 16:37:43` при Windows `16:37:43.564471`.
- Владелец подтвердил правильное время на дисплее и сохранение звука.
- Скрытый запуск автосинхронизации отдельно завершился успешно, отклонение около 0,48 секунды.

При подготовке репозитория переносимая Windows HID-реализация также проверена на чтении и реальной USB-синхронизации этой колонки. Физическую flash повторно ради упаковки репозитория не изменяли.

## Автоматические проверки

Unit-тесты проверяют wire format, ошибки протокола, подтверждение SET повторным GET, тайм-аут, защиту занятого запроса, SHA/границы пакета, отказ на неизвестной ревизии, откат после ошибки и сохранение новых настроек при восстановлении.

PI32v2-симулятор исполняет 24 сценария, включая аппаратно найденный случай длины в configuration descriptor, високосные даты, короткий приём, занятую очередь и ошибку `app_core`. USB/RTC API в модели подменены; модели не заменяют аппаратную проверку.

Собранный новый код побайтно сравнивается с кодом в опубликованном зашифрованном секторе. Локальная пересборка из оригинального дампа дала тот же SHA-256 пакета.

## Ограничения

- Проверена одна аппаратная ревизия. Название M82 и совпадение VID/PID не доказывают совместимость.
- Нажатие каждой из 16 мультимедийных кнопок отдельно не проверялось; их дескриптор сохранён.
- Полное обесточивание и сохранение времени после него отдельно не проверялись.
- Скрытый запуск проверялся непосредственно; полный выход/повторный вход в Windows в исходном тесте не выполнялся.
- Автозапуск синхронизирует один раз при входе, ждёт устройство около трёх минут и завершается. Он не отслеживает позднее переподключение весь день.
- Восстановление после полной потери USB через аппаратный загрузчик не проверялось.

## Исправления, включённые в опубликованную версию

Первая диагностическая сборка объявляла 51 байт в общем configuration descriptor при новом отчёте длиной 67 байт. Windows отклоняла HID-интерфейс. Обе длины приведены к 67; случай добавлен в модель.

Первая версия SET принимала возврат обёртки EP0 за число байт. По фактическому коду она возвращает адрес буфера после копирования. Ошибочная проверка удалена, модель исправлена; после этого выполнена успешная реальная синхронизация.
